# Add Restaurant

`$ARGUMENTS` の条件で実在店舗を探し、`data/restaurants.json` に追加する。
引数の都道府県が省略されたら `東京都`、件数が省略されたら `10`。

道具は `scripts/restaurant-tool.mjs` のみ使う。以下 `T` と書く:

```bash
T="node scripts/restaurant-tool.mjs"
```

## 絶対ルール（違反したら追加しない）

1. **WebFetch / WebSearch で今回実際に開いたページに書かれていることだけを書く。** 記憶・推測で店名、住所、メニュー、駅を書かない。
2. **料理idは `$T match` が出した候補からだけ選ぶ。** id を自分で作らない・推測しない。候補がなければその料理は紐づけない。
3. **閉店・移転・休業中・情報が2年以上前のものしかない店は追加しない。** 営業中と確認できない店は飛ばして次の店へ。
4. `data/restaurants.json` と `data/dishes.json` を Edit / Write しない。追記は `$T add` だけで行う。
5. `$T add` がエラーを出したら、エラー文に従って一時ファイルを直して再実行。3回失敗した店は諦めて飛ばす。

## 手順

### 1. 対象の確認

```bash
$T coverage                 # 料理圏ごとの「料理数 / 店あり / 未登録」
$T coverage <料理圏>         # その料理圏で店がまだない料理（id / 名前 / 別名）
```

`<料理圏>` は CLAUDE.md の「次元1」の表記どおり（例: `韓国料理`。`韓国` は不可）。
2つ目の出力が「この店で出していたら紐づけたい料理」の一覧。

### 2. 店の候補を探す

WebSearch で `<都道府県> <料理圏> 専門店`、`<未登録の料理名> <都道府県> 店` などを検索し、件数の1.5倍ほど候補を出す。

選ぶ基準（上ほど優先）:

- その料理圏の**専門店**（メニューが広く、1店で多くの料理を紐づけられる）
- 未登録の料理を出している店
- 公式サイトがある店
- チェーン店は1チェーン1店舗まで（本店か旗艦店）

既に登録済みでないか確認:

```bash
grep -c '"name": "<店名>"' data/restaurants.json   # 0 なら未登録
```

### 3. 1店ずつ情報を確認する

各店について WebFetch で次を開く:

- 公式サイト（あれば）: トップ / 店舗情報（住所・アクセス）/ メニュー
- 公式サイトがない場合: ホットペッパー・食べログ・TableCheck・自治体・媒体記事など**別々のサイトを2つ以上**

確認する項目とメモ:

- 店名（公式表記）と読み（ひらがな）
- 住所（都道府県から番地まで）、最寄り駅
- 現在営業しているか（最新の営業情報・SNS更新・予約受付）
- メニューに載っている料理名（**店の表記そのまま**で書き出す）

### 4. メニューと料理idの照合

メニュー名を1行1品で一時ファイルに書き、照合する:

```bash
cat > $TMPDIR/menu.txt <<'EOF'
サムギョプサル
海鮮チヂミ
石焼ビビンバ
EOF
$T match $TMPDIR/menu.txt
```

出力の読み方:

- `完全一致` → 採用してよい
- `部分一致` → 候補の説明（summary）を読み、**同じ料理なら**採用。「〜風」「〜ソース」など別物なら不採用
- `要確認` → 原則不採用。summary と店のメニュー説明が明らかに同じ料理のときだけ採用
- `(候補なし)` → 紐づけない（dishes.json への料理追加はこの手順ではやらない）
- 食材・調理法・ソースの id（`[食材]` `[調理法]` `[ソース]` 等）は、その名前の**料理**として出している場合以外は採用しない

採用した料理が **1品もない店は追加しない**。

### 5. 一時ファイルに店データを書く

`$TMPDIR/new-restaurants.json` に**配列**で書く。1回の add は最大10店。

```json
[
  {
    "id": "shop-name-area",
    "name": "店名 支店名",
    "kana": "てんめい してんめい",
    "cuisines": ["韓国料理"],
    "prefecture": "東京都",
    "area": "新宿区 大久保",
    "address": "東京都新宿区大久保1-2-3 ○○ビル1F",
    "nearestStation": "新大久保駅",
    "url": "https://example.com/",
    "description": "新大久保の韓国料理店。サムギョプサルやチヂミなどを出す。（30〜120字。ページに書かれた事実だけ。宣伝文句・主観は書かない）",
    "dishes": [
      { "id": "samgyeopsal" },
      { "id": "pajeon", "menuName": "海鮮チヂミ" }
    ],
    "checkedAt": "YYYY-MM-DD"
  }
]
```

フィールドのルール:

- `id`: 店名のローマ字 + 必要ならエリア。英小文字・数字・ハイフンのみ（例: `kanda-matsuya`, `erick-south-yaesu`）
- `name`: 公式表記。支店があるなら支店名まで
- `kana`: ひらがなのみ（カタカナ・英字不可）
- `cuisines`: CLAUDE.md 次元1の許可リストから。リストにない国（モンゴル・カンボジア等）は上位の圏（`アジア料理` / `東南アジア料理` / `アフリカ料理` / `北アフリカ料理`）
- `prefecture`: `東京都` `大阪府` のように「都道府県」まで書く
- `area`: `市区町村 地名`（例: `渋谷区 神宮前`）
- `address`: `prefecture` から始める
- `url`: 公式サイト。**ない場合は書かずに** `sources` に確認したURLを2件以上
- `sources`: 公式サイト以外で確認に使ったページのURL（公式があっても使ったら書く）
- `links`: 公式Instagram・予約ページなど（任意）`[{ "label": "Instagram", "url": "..." }]`
- `dishes[].menuName`: 店の表記が料理名と違うときだけ書く
- `dishes[].note`: 季節限定・要予約・ランチのみ等、ページに書いてあれば
- `checkedAt`: 今日の日付
- `closed` は書かない

### 6. 追加と検証

```bash
$T add $TMPDIR/new-restaurants.json   # 検証OKなら restaurants.json に追記＋整形
$T check                               # 全件チェック
python3 -c "import json; json.load(open('data/restaurants.json')); print('JSON valid')"
```

`$T add` は1件でもエラーがあると**何も追記しない**。エラーを直して再実行する。

### 7. 報告

最後に次をまとめて報告する:

- 追加した店（id / 店名 / 紐づけた料理数）
- 飛ばした店と理由（閉店・情報不足・照合ゼロ等）
- 迷って紐づけなかったメニュー名（人が後で判断する）
- `$T coverage` の該当料理圏の行（追加前後）
